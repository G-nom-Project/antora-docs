= AI Overview

G-nom offers native support for LLMs to improve interactive research. LLM's have access to a variety of Tools, allowing them to access contents of the G-nom database. The access restrictions of the user currently conversing with the agent apply. There are three major ways to connect AI Agents to G-nom:

. link:nativeai.html[*Native AI integration*]: Users interact with LLMs and data through G-nom's own chat interface in the browser. Credentials to access LLMs are provided either by the G-nom administrators during configuration (centralized) or configured by users under a BYOM / BYOK (bring your own model / key) approach. Instance administrators are still require to configure a small model for tool routing.
. link:mcp.html[*MCP server*]: The *M*odel-*C*ontext-*P*rotocol allows external AI agents to access data in G-nom through tools. G-nom's MCP server can be set up by activating a single feature flag but connecting to the MCP server requires more setup on the user side.
. link:librechat.html[*Librechat (or similar)*]: A compromise of both variants: G-nom instance administrators host an AI web interface using Librechat and provide a pre-configured MCP server (and optionally agent). Librechat provides a more feature-rich UI than the native AI integration and enables access to state-of-the-art AI features. Both a centralized model and BYOM/BYOK are possible, with option to limit BYOM providers i.e. to the internal AI provider of an university. Using arbitrary documents for RAG i.e. a curated paper collection can be archieved through Librechat, no longer requiring G-nom GROBID integration.
